═══ THE QUESTIONS THIS ANSWERS ═══
How does a new project register? Only through the admin API, with the admin key: POST /admin/projects → project id + one API key (shown once). The project then gets sheets created for it. Nothing else creates a project.
Is there an admin so only projects I allow may join? Yes: in production a sheet must exist in the registry and `open` must carry the project's API key; unknown sheet or wrong key → refused and logged. Autocreate is a development-only convenience.
Are we using sessions? A session = one authenticated WebSocket connection: id, project, sheet, remote addr, connected_at, last_seen, epoch, frames in/out. Kept in memory on the node it lives on, listable and killable through the admin API, written to audit_events on open/close/kick.
How do I kick a project off? Three levels, all immediate on every node: (1) kill one session; (2) suspend a project — every session closed with a `suspended` close frame, every `open` refused, data kept, reversible; (3) revoke a project — suspend + keys revoked + sheets dropped (exists today). Plus per-key revoke/rotate so one leaked key does not take a project down.

═══ DECISIONS — MADE. Log as D-024…D-031 with the alternative and why it lost. ═══
D-024 Admission: `open` gains optional `api_key` (additive, omitempty). Policy by REDLITE_ADMISSION: `password` (v1: sheet password only — advomedix cut-over), `key` (api_key required and must belong to the sheet's project; password still checked), default = `key` when REDLITE_ENVIRONMENT=production, `password` otherwise. A mismatch is `{"success":false,"error":"not authorized"}` — never "wrong password" vs "wrong key" (no oracle).
D-025 Autocreate default: REDLITE_SHEET_AUTOCREATE defaults true only when REDLITE_ENVIRONMENT=development; false otherwise. Autocreate never recreates a name that exists in the registry as revoked or suspended.
D-026 Sessions: in-memory `session.Registry` per node (map + RWMutex, keyed by session id = uuid), one entry per authenticated conn; the Conn carries its session id; last_seen updated on every inbound frame (atomic, no lock). No database table for live sessions (they are per-node and die with the process); open/close/kick rows go to audit_events (000002). Cross-node listing: GET /admin/sessions on a node returns that node's sessions plus `peer` sessions fetched from the peer's /admin/sessions (same admin key), merged, each row tagged with `node`.
D-027 Suspend: `projects.suspended_at timestamptz` (000002). POST /admin/projects/{id}/suspend and /resume. Suspend closes every session of the project on every node (close status 4001, reason "suspended") and refuses `open`; the project's sheets and entries stay in memory and in Postgres; the persist writer keeps flushing them. Resume lifts it. Propagated like revoke: NOTIFY redlite_control when persistence is on, else leader → replica over the stream as a control frame.
D-028 Keys: `api_keys` already has revoked_at. Add POST /admin/projects/{id}/keys (issue another; a project may hold many), DELETE /admin/keys/{id} (revoke one; sessions admitted with that key are closed, 4002 "key revoked"), POST /admin/keys/{id}/rotate (= issue new + revoke old in one tx, returns the new key once). `api_keys.last_used_at` updated at most once per minute per key (not per frame).
D-029 Listing: GET /admin/projects (id, name, created_at, suspended_at, key count, sheet count), GET /admin/projects/{id} (keys with prefix/created/revoked/last_used, sheets with key counts and collaborator counts), GET /admin/sheets/{name}/sessions, GET /admin/sessions. All read-only, all admin-key only. Paged with limit/cursor like backendAdvo (keyset on created_at,id; default 50, max 200).
D-030 Kick: DELETE /admin/sessions/{id} closes that one connection (4003 "kicked by admin"); the reader treats 4001/4002/4003 as terminal: no reconnect, Close() state, ErrAdmitted/ErrSuspended/ErrKicked surfaced to IsConnected callers via a new LastError(). Readers never retry a terminal close. 1000/1001/1006 and network errors keep the reconnect-forever behaviour (R1).
D-031 Peer auth: /replica and the peer /health probe require REDLITE_CLUSTER_TOKEN (Authorization: Bearer; constant-time compare). Missing or wrong → 401 before upgrade, nothing logged beyond remote addr and reason, no snapshot. Empty token in production refuses to start; empty in development logs Warn once. Readers do not use this token.
Admin key: unchanged (REDLITE_ADMIN_KEY, Bearer). Add POST /admin/admin-key/rotate? NO — admin key rotation is an env change and restart; document it in doc/release.md.
