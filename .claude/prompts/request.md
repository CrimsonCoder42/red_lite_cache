LOOPS — every behaviour you touch completes its loop as an integration test against a real leader:
 KEY LOOP: open → SET (ttl) → GET on a SECOND reader sees it → DELETE → second reader misses → GET after ttl misses on BOTH (R4/R5).
 SWEEP LOOP: SET 3 keys under one prefix + 1 outside → DELETE_PREFIX → the 3 gone on every reader, the 1 kept. Same for DELETE_SUFFIX.
 DISCONNECT LOOP (R1–R3): reader connected → kill the leader conn → Get misses while down → Delete issued while down → reconnect → the delete is applied before the first Get is served → reconnect happens with no attempt limit.
 RACE LOOP (R6): concurrent read-through Set of the old value vs a write + sweep → the old value never survives the sweep.
 REPLICA LOOP: leader + replica → writes reach the replica → kill the leader → replica promotes within heartbeat timeout → reader fails over → state intact.
 LOCK LOOP: A locks → B locked out → A disconnects → lock released → A stalls past TTL, B acquires, A's unlock is refused (not lock owner).
 PERSIST LOOP (needs REDLITE_TEST_DATABASE_URL, else SKIPPED: persist): set → flush → restart → hydrated; expired rows not loaded; full queue drops with a Warn, never blocks.
EDGE CASES — action before open · wrong password · empty sheet/password · malformed JSON · unknown action · oversized frame · unlock by non-owner · duplicate register_replica · server closing mid-write. Each gets an assertion, not a comment.
