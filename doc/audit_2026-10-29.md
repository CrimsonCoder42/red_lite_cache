# Audit — did the bootstrap improve advo_cache or copy it?

_2026-10-29, after commit 74eb999 + the port change. Method: grep and read the code on disk against
`SCOPE.md` K1–K16, `purpose.md` R1–R12, and the four `examples/` sources as distilled in
`doc/reference/`. The agent's final report was not used as evidence. Every row cites a file._

## Verdict

**Not a copy.** Every structural defect in the predecessor is gone from the code, each fix carries an
origin comment naming what it replaced (51 of them), and the test suite that advo_cache never had
exists (24 test files, 165 green under `-race`). Three things remain: one security hole the stream
example warned about and we reproduced (`/replica`), one piece that is cleverer than it should be
(the R6 miss window), and the Postgres paths that have never run.

## 4. What remains — ranked

### 4.1 `/replica` is unauthenticated and ships password hashes (HIGH, before any second project)

This is the one stream defect we rebuilt. Fix: a shared `REDLITE_REPLICA_TOKEN` checked on the
`/replica` upgrade (and on the peer `/health` probe), **or** the replica authenticates with a
registry API key of a `cluster` project. The hashes stay in the snapshot — that is K12's fix — but
only an authenticated peer may receive one. Test: EDGE case "replica without token → 401, no snapshot".

### 4.2 The R6 miss window is cleverer than it should be (MEDIUM, simplicity)

`reader/local.go:45-60` tracks per-key misses in half-window slices with fallback seqs; the server
keeps a 4 096-entry sweep log per sheet (`internal/sheet/sweeplog.go`). It is correct (`TestStaleWrite`,
`TestR6MissWindowReplaces`) and the reviewer measured its limit (>~136 writes/s on one sheet refuses
read-throughs for up to 30 s). The production-simple version is a **version-check write**: the miss
returns the sheet `seq` the reader observed; the read-through `set` carries it; the server rejects
if the sweep log shows any op covering the key after that seq. That is what the server half already
does — the reader-side slice bookkeeping exists only to avoid holding one seq per missed key. Hold a
bounded `map[key]seq` (evict oldest) instead and delete the slice machinery; the behaviour is
identical below the bound and degrades to "refuse" above it, which is what it does today. One
D-id, one PR, fewer lines.

### 4.3 Reader eviction has no policy (MEDIUM, the LRU example's whole point)

"First expired in 64, else arbitrary" is fine for correctness and bad for hit rate under pressure:
it can evict the hottest key. Two honest options, pick one as D-024: (a) sampled LRU the Redis way —
keep `lastAccess` per entry, sample 5, evict the oldest (two extra fields, O(1)); (b) a real LRU
with `container/list`, which is what `examples/build_your_own_cache.md` builds and costs a pointer
per entry plus a lock on every `Get`. Recommendation: (a). This is also the moment to write
`doc/reference/lru_cache.md` (still "not started" in `examples/README.md`).

### 4.4 R7 index is first-segment only (LOW–MEDIUM, measurable)

backendAdvo's grammar is `<root>:patient:<uuid>:<view>`; sweeps are by `<root>:patient:<uuid>`.
Indexing on the first segment groups by root, so a sweep scans every key of that root. A second
index on the first *two* segments (`root:patient:uuid`) makes the common sweep O(keys-in-that-profile).
Benchmark before and after with keys shaped like backendAdvo's (`bench_s1.txt` used flat keys).

### 4.5 Autocreate default lets a revoked sheet name come back (LOW while advomedix is the only tenant)

Flip the default to `false` the day a second project is registered; until then, refuse autocreate
of a name that exists in the registry as revoked (one lookup).

### 4.6 Unproven: everything Postgres (BLOCKING for v0.1.0)

11 tests skip without `REDLITE_TEST_DATABASE_URL`: hydration, flush fencing, revoke-by-NOTIFY,
advisory election. `docker compose up -d` + the env var runs them. Nothing Postgres-side should be
called done until that run is green once.

### 4.7 Smaller

- `internal/replica` has no unit tests (integration `TestReplicaLoop` only). Promotion edge cases
  (both nodes boot at once; peer unreachable but not dead) deserve table tests.
- `audit_events` (000002) is proposed, not applied — needs your approval, by design.
- `golang.org/x/time` is in `go.mod` but unused (admin rate limiting is a TODO); drop it or use it.
- `doc/reference/advo_cache.md` (file:line walkthrough of the predecessor) still not written; the
  origin comments now cover most of it, so it may be unnecessary — decide and close the row.
