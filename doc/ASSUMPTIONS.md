| Wire: R6 mechanism | New `base_seq` on `set` + a per-sheet sweep log (`REDLITE_SWEEP_LOG_WINDOW` 30s, `REDLITE_SWEEP_LOG_MAX` 4096). | Wire: expiry | `expires_in_ms` (relative) on the set reply, `replicate`, `sheet_state` and replica frames; `keys` on `invalidate` for one janitor pass | none (additive) | no |
| Wire: replica stream | Replicas speak on `/replica`: `register_replica` → reply with `epoch` → `snapshot_sheet` per sheet (with `password_hash`) → `snapshot_end` → live stream. `full_state`, `replicate_lock` and `replicate_unlock` are no longer sent; `register_replica` on `/ws` answers `register_replica moved to /replica`. | Replica: fencing peer | New `REDLITE_PEER_ADDRESS`: a leader probes the peer's `/health` each heartbeat interval and steps down to a peer with a higher epoch (D-012 needs to know whom to follow) | without it, a stale leader learns only from a reader write or a registering replica | no |

| D-012: who may fence | Only the peer probe (`REDLITE_PEER_ADDRESS` `/health`) steps a leader down. An epoch carried by a client request or a registering replica is refused (`stale epoch`) and only triggers an immediate probe: it is an unauthenticated claim. Without a peer a stale leader keeps leading, but every reader that saw the higher epoch refuses it | without a peer, a stale leader serves v1 readers that never saw the higher epoch until it restarts | no |
| D-021: revoke with autocreate on | `POST /admin/projects/{id}/revoke` removes the sheets, but with `REDLITE_SHEET_AUTOCREATE=true` (the v1 default) anyone can `open` the same name again and get a fresh, empty sheet in the default project. Revocation is only a lock-out with autocreate off — the setting a multi-project deployment runs | a revoked name can be re-claimed empty under the default config | no |
| D-021: revoke order | The revoke drops the sheets from memory and the writer before the Postgres transaction (so no queued op resurrects them).
