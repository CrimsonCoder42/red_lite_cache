| Persist: prefix/suffix SQL | `starts_with(key, $1)` / `right(key, length($1)) = $1` instead of the rule's `LIKE $1 \|\| '%'`, because an unescaped `_` or `%` in a key widens a LIKE match and deletes rows that should stay. `.claude/rules/backend/go-persist.md` should change to match | the rule and the code disagree until the rule is edited | no — rule edit is Devin's (`.claude/` is never edited by agents) |
| Persist: tenancy | `cache_entries` and `sheets` carry `project_id`; sheets autocreated by a v1 `open` belong to a seeded `default` project (all-zero uuid). Sheet names are globally unique (`sheets.name` PK) so a v1 `open` by name stays unambiguous | two projects cannot both own a sheet called `x` | no |
| Persist: expiry column | `cache_entries.expires_at` is nullable (NULL = no expiry, `REDLITE_CACHE_TTL=0`); design.md had NOT NULL | none | no |
| Persist: jsonb | Values are stored as `jsonb`: hydration returns them normalised (key order, whitespace) and a value containing `\u0000` is refused by Postgres (logged by the flush, memory unaffected) | a consumer comparing raw bytes after a restart sees reordered keys | no |
| Persist: who writes | Only the node that is currently leader persists and hydrates; leader and replica may share one database (docker-compose does) | two leaders during a partition both write until the stale one steps down | no |
| Wire: Request shape | One `protocol.Request` union struct (every action's fields, `action` discriminates) instead of a struct per action: one decode pass, one definition per field. K7 is fixed by the single package, not by splitting the struct | none | no |
| Wire: request id | New `id` on Request/Response so the reader matches acks among broadcasts (R9). Additive | none | no |
| Wire: R6 mechanism | New `base_seq` on `set` + a per-sheet sweep log (`REDLITE_SWEEP_LOG_WINDOW` 30s, `REDLITE_SWEEP_LOG_MAX` 4096). A set whose base is older than a covering set/delete, or older than the log, answers `stale write` and is not stored. Sets count as covering, so two concurrent read-throughs of the same key store only the first | a read-through slower than 30s is never cached (it is refused, never stale) | no |
| Wire: expiry | `expires_in_ms` (relative) on the set reply, `replicate`, `sheet_state` and replica frames; `keys` on `invalidate` for one janitor pass | none (additive) | no |
| Wire: replica stream | Replicas speak on `/replica`: `register_replica` → reply with `epoch` → `snapshot_sheet` per sheet (with `password_hash`) → `snapshot_end` → live stream. `full_state`, `replicate_lock` and `replicate_unlock` are no longer sent; `register_replica` on `/ws` answers `register_replica moved to /replica`. Only a v1 advo_cache *replica* is affected, and it is replaced together with the leader | a mixed advo_cache/red_lite_cache pair cannot replicate | no |
| Replica: locks | Locks are not replicated: their owners are connections, which a failover drops anyway; locks also have a TTL | a lock held across a failover is released | no |
| Replica: client opens | A replica that has not promoted refuses `open` with `not leader`, so a v1 reader's backup never takes writes the leader will not see | a reader pointed only at the replica cannot open until promotion | no |
| Replica: fencing peer | New `REDLITE_PEER_ADDRESS`: a leader probes the peer's `/health` each heartbeat interval and steps down to a peer with a higher epoch (D-012 needs to know whom to follow) | without it, a stale leader learns only from a reader write or a registering replica | no |
| Reader: deletes | `Delete*` return nil when the delete is queued for replay (v1 returned `ErrNotConnected`); `ErrClosed` only after Close | a consumer that logged ErrNotConnected stops seeing it (by design: R2) | no |
| Reader: sets | `SetWithTTL` waits for the server's ack (R9) and returns `ErrStale` for a refused read-through; v1 was fire-and-forget | one round trip per set on the read-through path | no |
| Reader: bound | `MaxEntries` default 100 000; a new key on a full map evicts an expired entry, else an arbitrary one | an evicted hot key costs one DB read | no |
| Testing: harness | `StartLeader` listens on `127.0.0.1:0` and runs the same `app.Run` the binary runs, instead of `httptest.Server`, so shutdown and the goroutine set are tested too | none | no |
| Testing: header style | `backendAdvo/testing/new_backend/` does not exist on 2026-10-29; the test header style is CLAUDE.md's `// Covers:` line alone | none | no |
| S1: sweep log bounds | `SweepLogWindow <= 0` or `SweepLogMax <= 0` means unbounded on that dimension (config always sets both) | none in production | no |
| S1: stale check scope | `base_seq` is checked for sets only; a delete is never stale. Deletes and sweeps always bump seq, broadcast and enter the sweep log even when nothing matched, so a sweep of uncached keys still refuses a stale read-through | one broadcast per no-op sweep | no |
| S1: full sheet | `MaxKeys` counts expired keys the janitor has not removed yet; overwriting an existing key is allowed on a full sheet | a sheet can refuse a new key up to one janitor interval early | no |
| S1: suffix "" | `delete_suffix ""` deletes every key (v1 `HasSuffix` semantics) | none | no |
| S1: lazy expiry | `Store.Get` never deletes an expired key; the janitor removes it so the removal is broadcast and persisted | memory held up to one janitor interval | no |
| S2: lock expiry | `unlock` of an expired lock answers `lock not found` (whoever held it) and removes it | none | no |
| S2: logging | stale write, key not found and sheet not found refusals log at Debug; every other refusal (incl. lock held) at Warn | Warn volume under lock contention | no |
| S2: set_null TTL | `set_null` honours `ttl` when sent (v1 always used the default; v1 clients send none) | none | no |
| S2: close codes | kick → 1001, wrong password → 1008, frame over limit → 1009 | none | no |
| S2: origin | `/ws` uses coder/websocket's default origin policy: no Origin header (every backend) is accepted, a cross-origin browser is refused | a browser client on another origin cannot connect | no |
| S2: error suffixes | v1's `unknown action: <name>` and `already in sheet: <id>` lose the suffix (constants in protocol/) | a client matching the full v1 string misses it; backendAdvo never does | no |
| S3: seq on reconnect | a `sheet_state` *sets* the reader's applied seq (not max), so a restarted server's lower seq is honoured | none | no |
| S3: miss overflow | on miss-record overflow, keys without a record send the lowest dropped seq (conservative) | more refused read-throughs after overflow | no |
| S3: backoff | backoff resets after a connection that lasted min(ReconnectMax, 10s); after a drop the same address is retried first, a failed attempt switches address | none | no |
| S3: write refusals | a `not leader` / `stale epoch` reply ends the link and fails over; an unacked or timed-out delete resets the link and requeues | a flapping server costs reconnects | no |
| S3: id-less replies | a reply without `id` matches the oldest pending request (a v1 server works); ids are assigned and written under one per-session lock | none | no |
| S3: null in Has/GetRaw | `Has` is true and `GetRaw` returns `"__NULL__"` for a null placeholder (v1 shape); only `Get` treats it as a miss | none | no |
| S5: flush logging | a completed flush logs at Debug (Info every 5 s is noise); every flush is bounded by 10 s; the shutdown drain reads at most cap(queue) ops | none | no |
| D-012: who may fence | Only the peer probe (`REDLITE_PEER_ADDRESS` `/health`) steps a leader down. An epoch carried by a client request or a registering replica is refused (`stale epoch`) and only triggers an immediate probe: it is an unauthenticated claim. Without a peer a stale leader keeps leading, but every reader that saw the higher epoch refuses it | without a peer, a stale leader serves v1 readers that never saw the higher epoch until it restarts | no |
| D-021: revoke with autocreate on | `POST /admin/projects/{id}/revoke` removes the sheets, but with `REDLITE_SHEET_AUTOCREATE=true` (the v1 default) anyone can `open` the same name again and get a fresh, empty sheet in the default project. Revocation is only a lock-out with autocreate off — the setting a multi-project deployment runs | a revoked name can be re-claimed empty under the default config | no |
| D-021: revoke order | The revoke drops the sheets from memory and the writer before the Postgres transaction (so no queued op resurrects them). If that transaction fails the route answers 500: keys stay valid and rows stay in Postgres until the revoke is retried; a restart in between hydrates them back | a failed, un-retried revoke is undone by a restart | no |
| D-020/D-022 | Revoke answers 204 with no body; `persist.Control` (the NOTIFY payload) lives in internal/persist because it only travels through Postgres; in advisory mode a boot leader that gets the lock promotes to stored+1; the elector releases the lock at shutdown before the last flush; leader and replica must share one `REDLITE_PERSIST_LOGGED` value or each boot flips the table | config drift flips cache_entries durability | no |
| Replica path auth | `/replica` has no authentication (neither did advo_cache): anyone who can reach the port can register and receive every sheet's snapshot, password hashes included. Keep the port on the private network (Tailscale) until a replica key exists | tenant data and hashes readable from the replica port | no — `doc/TODO.md` |
| S4: follow target | a stepped-down leader follows `REDLITE_PEER_ADDRESS`, else `REDLITE_LEADER_ADDRESS`; only with neither is it fenced | none | no |
| S4: dial backoff | replica dial 50 ms doubling to 5 s, full jitter, forever | none | no |
| S4: boot | a hydration failure fails `app.New`; a lone replica that never synced promotes after the heartbeat timeout (hydrating first with persistence); a promotion whose epoch write fails still happens on the in-memory epoch | a DB outage at promotion leaves the stored epoch behind | no |
| S4: heartbeat | only frames that pass the epoch check reset the heartbeat timer | none | no |
| S5: retry | a size-triggered flush counts as "the next tick" for the one retry; the shutdown flush has no retry | a shutdown during a DB outage loses the last batch's durability | no |
